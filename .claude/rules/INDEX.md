# Repository rules

The rules under `.claude/rules/` are part of the root `AGENTS.md`'s contract. Claude Code loads each one by itself when a file under its `paths:` is touched. Cursor reads each one through `.cursor/rules/<name>.mdc`, a committed file generated from the rule: its `paths:` become Cursor's `globs:`, so Cursor attaches the rule by itself when a matching file is in context, and a rule without `paths:` becomes `alwaysApply: true`. Codex reads each one as the skill `.agents/skills/rule-<name>/SKILL.md`, generated from the rule with its paths in the description, and every nested `AGENTS.md` as a `guide-<dir>` skill that points at it. So on Codex, and on Cursor when the rule is not already in context, open the matching rule and follow it before editing a file under its paths.

A rule's frontmatter holds only a one-line `description:` and an optional `paths:` block list with no brace group (Cursor splits `globs:` on commas), and the script refuses anything else. `pnpm sync:agent-rules --check` (in CI and `full-check`) fails on a missing, stale or extra file, and when a rule has no row here, a row names no rule, or a row's paths differ from its rule's `paths:` (a brace group in a cell stands for each of its expansions).
